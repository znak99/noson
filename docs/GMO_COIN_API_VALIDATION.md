# GMO Coin Public API 사용 가능성 검증

## 1. 문서 정보

### 1.1 목적

이 문서는 Noson MVP의 주 시장 데이터 공급자 후보인 `GMO Coin Public API`가 다음 요구사항을 충족하는지 검증한 결과를 기록한다.

- 회원 계정과 API Key 없이 시장 데이터를 조회할 수 있는가?
- `BTC`, `ETH`, `XRP`, `SOL`, `DOGE` 현물 데이터를 모두 제공하는가?
- 현재가, 최우선 Bid/Ask, 24시간 고가·저가·거래량과 1분봉 OHLCV를 제공하는가?
- 주문 최소 수량, 수량 단위, 호가 단위와 Maker/Taker 수수료를 확인할 수 있는가?
- 비수익 제3자 모바일 앱에서 데이터를 표시하고 모의 체결에 사용할 수 있는가?

### 1.2 확인 정보

| 구분 | 내용 |
|---|---|
| 확인일 | 2026-08-13 |
| 시간대 | Asia/Tokyo |
| 확인 방식 | GMO Coin 공식 문서 검토 및 Public REST/WebSocket 읽기 전용 실응답 확인 |
| 계정·인증 사용 | 사용하지 않음 |
| 실제 주문 전송 | 수행하지 않음 |

### 1.3 결론

**GMO Coin Public API는 기술적으로 적합하지만 이용 조건 확인이 필요한 조건부 주 데이터 공급자다.**

| 판단 항목 | 결과 | 근거 |
|---|---|---|
| 인증 없는 시장 데이터 조회 | 적합 | Public REST와 Public WebSocket은 인증을 요구하지 않는다. |
| MVP 5개 현물 종목 | 적합 | 5개 종목 모두 공식 지원 목록과 실응답에서 확인됐다. |
| 현재가·Bid/Ask·24시간 통계 | 적합 | REST ticker와 WebSocket ticker가 필요한 필드를 제공한다. |
| 1분봉 OHLCV | 조건부 적합 | 필요한 필드는 제공하지만 거래가 없는 분은 봉이 없을 수 있고 데이터 날짜는 일본시간 06:00에 전환된다. |
| 정밀도·최소 주문 단위·수수료 | 적합 | `/public/v1/symbols` 실응답에서 종목별 값을 확인했다. |
| 무료 운영 | 조건부 적합 | Public API는 인증 없이 접근할 수 있지만 Public REST의 정량 호출 상한과 SLA는 공개 문서에서 확인되지 않았다. |
| 제3자 앱 시세 재표시 | 미확정 | 가격 자동 취득은 공식적으로 안내되지만 제3자 앱 재표시·가공·저장·Cloudflare 정기 조회 허용 범위는 명시되지 않았다. |

따라서 다음 원칙을 적용한다.

- API 어댑터와 도메인 계산처럼 공급자 교체가 가능한 내부 작업은 진행할 수 있다.
- GMO Coin 데이터를 사용자에게 표시하는 배포용 연동은 GMO Coin의 서면 답변을 받은 뒤 확정한다.
- 답변 전에는 GMO Coin 로고나 제휴로 오인될 표현을 사용하지 않는다.
- 허용되지 않거나 무료 운영 조건과 맞지 않으면 `Coincheck Public API` 등 대체 공급자를 별도 검증한다.

## 3. 공식 API 계약

### 3.1 엔드포인트와 인증

| 용도 | 엔드포인트 | Noson 사용 여부 |
|---|---|---|
| Public REST | `https://api.coin.z.com/public/v1` | 사용 후보 |
| Public WebSocket | `wss://api.coin.z.com/ws/public/v1` | 사용 후보 |
| Private REST | `https://api.coin.z.com/private/v1` | 사용 금지 |
| Private WebSocket | `wss://api.coin.z.com/ws/private/v1` | 사용 금지 |

Noson은 Public API만 사용하며 GMO Coin 계정, API Key 또는 API Secret을 요구하거나 저장하지 않는다.

### 3.2 필요한 REST API

| API | 목적 | 주요 응답 |
|---|---|---|
| `GET /status` | 거래소 운영 상태 확인 | `OPEN`, `PREOPEN`, `MAINTENANCE` |
| `GET /ticker` | 현재가와 24시간 통계 초기 조회 | `ask`, `bid`, `last`, `high`, `low`, `volume`, `timestamp` |
| `GET /orderbooks?symbol=...` | 종목별 주문서와 최우선 호가 확인 | `asks`, `bids`, `symbol` |
| `GET /klines?symbol=...&interval=1min&date=YYYYMMDD` | 차트와 지정가 모의 체결 판정 | `openTime`, `open`, `high`, `low`, `close`, `volume` |
| `GET /symbols` | 주문 규칙과 현재 수수료 확인 | `minOrderSize`, `maxOrderSize`, `sizeStep`, `tickSize`, `takerFee`, `makerFee` |

공식 문서는 전체 종목의 ticker가 필요할 때 `symbol`을 생략한 단일 요청을 권장한다. 앱의 종목 목록 초기화도 한 번의 `GET /ticker` 후 MVP 5개 종목만 필터링하는 방식을 우선한다.

### 3.3 WebSocket 계약과 제한

- `ticker` 채널은 `ask`, `bid`, `last`, `high`, `low`, `volume`을 문자열로 제공하며 `timestamp`는 체결 시각이다.
- `orderbooks` 채널은 종목별 `asks`, `bids`와 배포 시각을 제공한다.
- 동일 IP의 `subscribe`와 `unsubscribe`는 합산하여 초당 1회가 상한이다.
- 서버는 1분마다 ping을 보내며 pong이 3회 연속 없으면 연결을 종료한다.
- Public REST의 구체적인 초당 호출 상한은 확인한 공식 문서에 제시되지 않았다. 다만 시스템 부하 또는 사용 방식에 따라 제한될 수 있다고 안내한다.

MVP 5종목 구독은 최소 1초 이상의 간격을 두고 순차 등록해야 한다. 재연결 때도 동시에 구독 요청을 전송하지 않는다.

### 3.4 문자열과 시간 데이터

- 가격, 수량, 거래량, 수수료율은 JSON 문자열로 수신한다.
- API 경계에서 `double`로 변환하지 않고 이후 결정할 고정 정밀도 또는 10진수 표현으로 파싱한다.
- ticker와 WebSocket의 시각은 UTC ISO 8601 문자열이다.
- KLine의 `openTime`은 밀리초 단위 Unix timestamp 문자열이다.
- `YYYYMMDD` KLine 날짜는 자정이 아니라 일본시간 06:00에 전환된다.

## 4. 2026-08-13 실응답 검증

### 4.1 검증 방법

- Public REST는 `curl`로 요청하고 `status == 0`과 필수 필드 존재 여부를 확인했다.
- Public WebSocket은 Dart `WebSocket` 클라이언트로 연결했다.
- 구독 제한을 지키기 위해 종목별 `subscribe` 사이에 1.1초 간격을 뒀다.
- Private API, 계정, API Key와 실제 주문은 사용하지 않았다.
- 검증 시간은 대략 20:06~20:12 JST였다.

| ticker 필수 필드 | 성공 | 성공 | 성공 | 성공 | 성공 |

### 4.3 1분봉의 빈 구간

동일한 날짜와 시간대에 반환된 1분봉 개수는 다음과 같았다.

| 종목 | 반환된 봉 수 |
|---|---:|
| BTC | 740 |
| ETH | 412 |
| XRP | 533 |
| SOL | 329 |
| DOGE | 199 |

첫 봉의 `openTime`은 대체로 일본시간 06:00 부근이었고 마지막 봉은 조회 직전 체결 시각 부근이었다. 종목별 봉 수가 경과한 분 수보다 적고 서로 다르므로 거래가 없는 분에 대해 빈 봉이 자동 생성된다고 가정할 수 없다.

지정가 주문 체결 판정에서는 다음 규칙을 적용해야 한다.

- 봉이 없는 분은 가격이 지정가에 도달했다는 증거가 없는 것으로 처리한다.
- 이전 봉을 복제하거나 임의의 0 거래량 봉을 만들어 체결시키지 않는다.
- `openTime`을 기준으로 주문 생성 이후의 봉만 사용하고 이미 처리한 봉을 중복 적용하지 않는다.
- 일본시간 06:00 날짜 전환을 고려해 전일·당일 조회 범위를 계산한다.

상세 Cron 조회와 누락 복구 전략은 지정가 주문 백엔드 구현 전에 별도로 결정한다.

### 4.4 WebSocket 결과

| 검증 | 결과 |
|---|---|
| Public WebSocket 연결 | 성공 |
| 5종목 orderbooks 구독 | 성공 |
| 종목별 Ask/Bid 30개 스냅샷 | 5종목 모두 성공 |
| ticker 구독 후 45초 관찰 | BTC 메시지만 수신, ETH·XRP·SOL·DOGE는 관찰 시간 내 미수신 |

ticker 메시지의 `timestamp`가 체결 시각이고 실측상 모든 종목의 초기 값이 즉시 오지 않았으므로, 앱 최초 화면을 WebSocket ticker만으로 초기화하지 않는다.

권장 초기 흐름은 다음과 같다.

```text
GET /status
  → GET /ticker 한 번으로 5종목 초기 값 확보
  → Public WebSocket 연결
  → 1.1초 이상 간격으로 5종목 ticker 또는 orderbooks 구독
  → 수신 메시지로 초기 REST 값을 갱신
```

## 5. 주문 규칙과 수수료 실응답

`GET /public/v1/symbols`에서 2026-08-13에 확인한 값이다. 수수료는 소수 비율과 백분율을 함께 표시한다.

| 종목 | 최소 주문 수량 | 최대 주문 수량 | 수량 단위 | 호가 단위 | Taker | Maker |
|---|---:|---:|---:|---:|---:|---:|
| BTC | 0.00001 | 5 | 0.00001 | ¥1 | 0.0005 / 0.05% | -0.0001 / -0.01% |
| ETH | 0.001 | 100 | 0.0001 | ¥1 | 0.0005 / 0.05% | -0.0001 / -0.01% |
| XRP | 1 | 100,000 | 1 | ¥0.001 | 0.0005 / 0.05% | -0.0001 / -0.01% |
| SOL | 0.01 | 500 | 0.01 | ¥1 | 0.0009 / 0.09% | -0.0003 / -0.03% |
| DOGE | 10 | 200,000 | 1 | ¥0.001 | 0.0009 / 0.09% | -0.0003 / -0.03% |

Maker의 음수 수수료는 비용이 아니라 리베이트를 의미한다. 계산 구현에서는 부호를 보존해야 하며, 지정가 주문이 항상 Maker라고 가정하지 않는다. 정확한 Maker/Taker 판정과 반올림 규칙은 주문·자산 계산 설계에서 별도로 확정한다.

이 값은 변경될 수 있으므로 코드에 영구 상수로 확정하지 않는다. 최소한 구현 착수와 출시 전에는 `/symbols`와 공식 수수료 안내를 다시 확인하고 확인 날짜를 기록한다.

## 6. GMO Coin 문의 문안

### 6.1 확인이 필요한 사항

1. 비수익 제3자 iOS·Android 앱에서 Public REST/WebSocket 가격을 표시할 수 있는가?
2. 가격을 로컬 캐시하고 차트·가상 자산 계산·모의 주문 체결에 가공 사용할 수 있는가?
3. Cloudflare Worker가 앱 종료 중 1분봉을 정기 조회해 가상 지정가 주문을 판정할 수 있는가?
4. 출처 표시, 저작권 문구, 상표 사용 또는 별도 허가가 필요한가?
5. Public REST의 IP·설치본별 호출 상한과 권장 조회 주기는 무엇인가?
6. App Store와 Google Play 배포 시 추가 조건이 있는가?

답변을 받기 전까지 GMO Coin은 조건부 주 데이터 공급자 상태를 유지한다. 접수 확인 메일이나 답변에 문의 번호가 포함되면 이 표를 갱신하고, 답변 원문을 보존한 뒤 제3자 재표시·가공·정기 조회·표시 조건·호출 제한·스토어 배포 조건별로 판정을 기록한다.

## 7. 최종 채택과 대체 검토 기준

### 7.1 GMO Coin 채택 확정 조건

다음 조건을 모두 만족하면 GMO Coin Public API를 주 데이터 공급자로 확정한다.

- 제3자 모바일 앱의 시세 재표시와 가공 이용에 대한 서면 허용을 확보한다.
- Cloudflare Worker의 정기적 1분봉 조회가 허용된다.
- 필요한 출처 표시가 앱의 비제휴·비추천 원칙과 충돌하지 않는다.
- Public REST의 권장 조회 주기로 무료 운영과 지정가 주문 판정이 가능하다.
- MVP 5종목과 필요한 REST/WebSocket 필드가 구현·출시 시점에도 유지된다.

### 7.2 대체 공급자 검토 조건

다음 중 하나가 발생하면 GMO Coin 연동을 출시하지 않고 대체 공급자를 검토한다.

- 제3자 앱 표시, 데이터 가공 또는 백엔드 정기 조회가 허용되지 않는다.
- 유료 계약이나 비용 발생이 필수다.
- 요구되는 표시가 제휴·추천으로 오인될 위험을 해소할 수 없다.
- 호출 제한으로 5종목의 화면 갱신 또는 지정가 주문 판정이 안정적으로 불가능하다.
- 지원 종목이나 필요한 데이터 필드가 제거된다.
- 문의에 답변이 없고 다른 공식 근거로도 이용 권한을 확인할 수 없다.

대체 공급자 역시 같은 기술·약관·비용 검증을 먼저 수행하며 MVP에서 두 공급자를 동시에 구현하지 않는다.

## 8. 남은 위험과 재확인 시점

- 이번 실응답 검증은 단일 시점의 성공을 확인한 것이며 가용성 SLA를 의미하지 않는다.
- Public REST의 정량 호출 상한과 제3자 재표시 권한은 GMO Coin 답변이 필요하다.
- 수수료, 최소 주문 단위, 지원 종목과 응답 형식은 변경될 수 있다.
- 구현 시 네트워크 오류, 타임아웃, 빈 KLine, 중복 봉, WebSocket 재연결을 테스트해야 한다.
- GMO Coin 답변을 받았을 때, 시장 데이터 연동 구현 직전, 스토어 제출 직전에 이 문서를 갱신한다.
