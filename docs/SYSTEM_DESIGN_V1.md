# Noson MVP 시스템 설계 V1

## 1. 문서 정보

### 1.1 목적

이 문서는 일본 출시를 목표로 하는 암호화폐 모의투자 앱 `Noson(ノー損)`의 MVP 범위와 시스템 경계를 정의한다.

이 프로젝트는 1인 개발과 AI Agent 중심의 개발을 전제로 한다. 따라서 이 문서는 모든 구현 세부사항을 고정하는 명세서가 아니라, 개발 중 반드시 유지해야 하는 제품 원칙과 기술 방향을 제공하는 기준 문서이다.

### 1.2 문서 사용 원칙

- AI Agent는 기능을 설계하거나 구현하기 전에 이 문서를 확인한다.
- 이 문서의 `확정` 항목은 별도 합의 없이 변경하지 않는다.
- `구현 시 결정` 항목은 실제 작업 직전에 사용자와 논의하여 구체화한다.
- `출시 전 확인` 항목은 구현 완료 여부와 별개로 스토어 제출 전에 최신 공식 정보를 다시 확인한다.
- 새 결정이 기존 내용에 영향을 주면 관련 구현과 이 문서를 함께 갱신한다.
- 세부 구현이 이 문서와 충돌하면 임의로 우회하지 않고 사용자에게 확인한다.

### 1.3 결정 상태

| 상태 | 의미 |
|---|---|
| `확정` | MVP에서 유지해야 하는 제품 또는 기술 결정 |
| `구현 시 결정` | 방향만 정해졌으며 작업 직전에 상세화할 항목 |
| `출시 전 확인` | 약관, 수수료, 법률, 스토어 정책 등 최신 정보 확인이 필요한 항목 |
| `대체 후보` | 현재 구현 대상은 아니며 주 선택지를 사용할 수 없을 때만 검토할 항목 |

## 2. 제품 정의

### 2.1 한 문장 정의

> Noson은 실제 시장 데이터를 이용해 암호화폐 현물 거래를 가상으로 체험하는 일본어 모의투자 앱이다.

### 2.2 목표

| 구분 | 확정 내용 |
|---|---|
| 앱 이름 | `Noson(ノー損)` |
| 출시 대상 | 일본 App Store 및 Google Play |
| 핵심 사용자 가치 | 실제 돈을 사용하지 않고 암호화폐 거래 경험 제공 |
| 거래 대상 | 암호화폐 현물 |
| 기준 통화 | JPY |
| 수익화 | 하지 않음 |
| 비용 목표 | 개발비와 운영비 `¥0` 유지 |
| 개발 방식 | 1인 개발과 AI Agent 중심의 빠른 개발 |
| 구조 원칙 | 과도한 확장성보다 단순한 구조와 실제 출시 우선 |

### 2.3 절대 원칙

다음 원칙은 MVP에서 변경하지 않는다.

1. 실제 금융거래를 수행하지 않는다.
2. 실제 암호화폐의 매수, 매도, 보관, 송금 또는 입출금 기능을 제공하지 않는다.
3. 거래소 계정, 거래소 API Key 또는 암호화폐 지갑을 연결하지 않는다.
4. GMO Coin을 포함한 거래소 가입이나 실제 거래를 유도하지 않는다.
5. 투자 추천, 종목 추천, 수익 보장에 해당하는 기능이나 표현을 제공하지 않는다.
6. 앱에 표시되는 자산, 수익 및 손실은 모두 가상 데이터이다.
7. 앱이 실제 금융서비스로 오인되지 않도록 주요 사용자 접점에서 시뮬레이션임을 명확히 알린다.

### 2.4 MVP 제외 범위

다음 항목은 MVP에 포함하지 않는다.

- 실제 암호화폐 거래 및 금융 자산 보관
- 암호화폐 또는 법정화폐 입출금
- 거래소 계정, API Key 또는 지갑 연결
- 레버리지 및 선물 거래
- 거래소 가입 유도
- 투자 추천, 종목 추천 또는 수익 보장 표현
- 회원가입 및 서버 기반 사용자 계정
- 광고, 인앱결제 또는 기타 수익화 기능
- 캔들차트 및 전체 호가창과 같은 전문 트레이딩 UI
- GMO Coin의 전체 현물 종목 지원

## 4. MVP 기능 범위

### 4.1 지원 종목

MVP는 다음 5개 종목만 지원한다.

| 심볼 | 자산 |
|---|---|
| `BTC` | Bitcoin |
| `ETH` | Ethereum |
| `XRP` | XRP |
| `SOL` | Solana |
| `DOGE` | Dogecoin |

### 4.2 메인 화면 구조

앱은 `종목`, `자산`, `메뉴`의 3개 메인 탭으로 구성한다.

#### 종목 탭

지원 종목의 시장 상황을 한 화면에서 제공한다.

- 현재가
- 24시간 등락률
- 24시간 미니 라인 차트
- 종목 상세 화면 진입

종목 상세 화면은 다음 정보를 제공한다.

- 현재가
- 24시간 등락률
- 24시간 고가 및 저가
- 거래량
- 가격 라인 차트
- 매수 및 매도 화면 진입

#### 자산 탭

다음 모의투자 정보를 제공한다.

- 전체 보유 자산
- JPY 잔액
- 암호화폐 보유 내역
- 평가손익 및 평가손익률
- 거래내역
- 미체결 지정가 주문

#### 메뉴 탭

앱 설정을 제공한다. 세부 설정 항목은 `구현 시 결정`한다.

### 4.3 최초 실행 및 온보딩

최초 실행 흐름은 다음과 같다.

```text
스플래시
  → 모의투자 앱 안내
  → 실제 금융거래가 아님을 명시
  → 가상자금 ¥1,000,000 지급
  → 종목 탭 진입
```

온보딩은 1~2개 화면으로 최소화하며 다음 내용을 반드시 알린다.

- 실제 암호화폐 거래가 아닌 시뮬레이션 앱이다.
- 앱의 모든 자산과 손익은 가상 데이터이다.

회원가입, 투자성향 입력 또는 관심종목 선택은 요구하지 않는다.

### 4.4 초기 가상자금과 리셋

- 최초 가상자금은 `¥1,000,000`이다.
- 앱 최초 시작 시점을 기준으로 3개월이 지나면 리셋 가능한 상태로 판단한다.
- 3개월 경과 시 자동으로 리셋되는 것이 아니라, 리셋 가능 여부를 판단하는 기준으로 사용한다.
- 리셋 UX, 상태 전이 및 예외 규칙은 `구현 시 결정`한다.

## 5. 거래 도메인 규칙

### 5.1 지원 주문 유형

| 주문 유형 | 체결 위치 | 기본 가격 | 앱 종료 중 체결 |
|---|---|---|---|
| 시장가 주문 | Flutter 앱 | 매수는 현재 Ask, 매도는 현재 Bid | 해당 없음 |
| 지정가 주문 | Cloudflare 백엔드 | 사용자가 지정한 가격 | 지원 |

### 5.2 시장가 주문

- 앱에서 즉시 체결한다.
- 시장가 매수는 현재 Ask 가격을 기준으로 한다.
- 시장가 매도는 현재 Bid 가격을 기준으로 한다.
- 체결 결과, 수수료 및 자산 변동은 로컬 데이터에 반영한다.

### 5.3 지정가 주문

지정가 주문은 앱이 종료된 상태에서도 체결될 수 있어야 하므로 Cloudflare 기반 최소 백엔드에서 처리한다.

확정된 체결 규칙은 다음과 같다.

- 지정가 매수는 주문 생성 후의 1분봉 Low가 지정가 이하일 때 체결한다.
- 지정가 매도는 주문 생성 후의 1분봉 High가 지정가 이상일 때 체결한다.
- 체결 가격은 사용자가 지정한 가격이다.
- 부분 체결은 지원하지 않는다.
- 주문은 사용자가 취소할 때까지 유지한다.
- 주문 생성 시 체결에 필요한 JPY 또는 암호화폐를 예약한다.
- 주문 생성 이전의 가격 움직임으로 체결하지 않는다.

기본 처리 흐름은 다음과 같다.

```text
앱에서 주문 입력
  → 주문 유효성 확인 및 자산 예약
  → 익명 Installation ID와 함께 백엔드에 등록
  → Cron이 주문 생성 이후의 시장 데이터를 확인
  → 체결 조건 충족 시 전체 수량을 지정가로 체결
  → 체결 결과 저장
  → 앱이 결과를 동기화하여 로컬 자산과 내역에 반영
```

주문 상태, 중복 처리 방지, 취소와 체결의 경합, 결과 동기화 및 실패 복구 방식은 `구현 시 결정`한다.

### 5.4 거래 수수료

- 수수료를 생략하지 않고 모의 거래 비용에 반영한다.
- 시장가 주문은 Taker 성격의 수수료를 반영한다.
- 주문 생성 이후의 미래 1분봉으로 체결되는 지정가 주문은 Maker로 처리한다.
- 수수료는 체결내역과 자산 계산에 반영한다.
- 정확한 수수료율과 Maker/Taker 판정은 구현 시점의 GMO Coin 공식 정책을 확인한 뒤 결정한다.

2026-08-13의 `/public/v1/symbols` 실응답에서는 `BTC`, `ETH`, `XRP`의 Taker가 `0.05%`, Maker가 `-0.01%`이고, `SOL`, `DOGE`의 Taker가 `0.09%`, Maker가 `-0.03%`였다. 음수 Maker 수수료는 비용이 아니라 리베이트이므로 계산할 때 부호를 보존한다. 상세 값과 검증 근거는 `docs/GMO_COIN_API_VALIDATION.md`를 따른다.

수수료 정책 확인은 `출시 전 확인` 항목이면서 관련 기능 구현 전에도 필요한 선행 작업이다. 현재 확인값을 영구 상수로 확정하지 않고 구현 착수와 출시 전에 `/symbols`와 GMO Coin 공식 수수료 안내를 다시 확인한다.

### 5.5 자산 계산

확정된 계산 원칙은 다음과 같다.

- 종목별 보유 수량을 관리한다.
- 종목별 평균 매입가를 관리한다.
- 추가 매수 시 가중평균 방식을 사용한다.
- 현재가를 이용해 종목별 평가금액을 계산한다.
- 평가손익과 평가손익률을 제공한다.
- 전체 자산은 `보유 JPY + 암호화폐 평가금액`으로 계산한다.
- 미체결 지정가 주문에 필요한 자산은 주문 기간 동안 예약한다.

### 5.6 수치 표현과 계산 규칙

다음 규칙은 MVP의 앱과 Cloudflare 백엔드에 공통으로 적용한다.

#### 고정소수점과 외부 경계

- 금액, 가격, 수량, 수수료율과 손익은 소수점 이하 12자리의 `BigInt` 기반 고정소수점으로 계산한다.
- `double` 또는 이진 부동소수점으로 시장 데이터와 자산 값을 변환하지 않는다.
- REST, WebSocket, Drift/SQLite 및 Cloudflare 경계에서는 10진 문자열을 사용한다. Drift 상세 스키마를 구현할 때도 수치 원문을 보존할 수 있는 `TEXT` 저장을 기본으로 한다.
- 지수 표기와 소수점 이하 12자리를 넘는 입력은 반올림하지 않고 거부한다.
- 곱셈, 나눗셈 및 비례 배분 결과가 12자리를 넘을 때는 절댓값을 기준으로 가장 가까운 값으로 반올림하고 정확히 절반이면 0에서 먼 방향으로 처리한다.

2026-08-13에 GMO Coin `/public/v1/symbols`에서 확인한 MVP 종목 규칙은 다음과 같다. 이 값은 공급자 응답으로 갱신하며 영구 상수로 간주하지 않는다.

| 종목 | 가격 단위 | 최소 주문 수량 | 수량 단위 | 최대 주문 수량 | 가격 표시 소수 자릿수 | 수량 표시 소수 자릿수 |
|---|---:|---:|---:|---:|---:|---:|
| `BTC` | `1` | `0.00001` | `0.00001` | `5` | 0 | 5 |
| `ETH` | `1` | `0.001` | `0.0001` | `100` | 0 | 4 |
| `XRP` | `0.001` | `1` | `1` | `100000` | 3 | 0 |
| `SOL` | `1` | `0.01` | `0.01` | `500` | 0 | 2 |
| `DOGE` | `0.001` | `10` | `1` | `200000` | 3 | 0 |

사용자 주문 가격과 수량이 종목별 단위의 배수가 아니면 자동 보정하지 않고 입력 오류로 처리한다. 최소·최대 주문 수량과 가용 자산도 체결 전에 검증한다.

#### 수수료와 주문 예약

- 시장가 주문은 Taker, 주문 생성 이후의 미래 1분봉으로 체결된 지정가 주문은 Maker로 처리한다.
- `수수료 = 체결 가격 × 체결 수량 × 수수료율`로 계산하며 Maker의 음수 수수료는 리베이트이므로 부호를 보존한다.
- GMO Coin은 실제 현물 거래에서 체결별 엔 미만 수수료를 단수 처리하고 일본시간 06:00에 종목별 단수를 합산 정산한다. Noson은 이 일일 정산 상태를 모방하지 않고 12자리 고정소수점의 정확한 수수료를 즉시 반영한다. 이 단순화는 2026-08-13에 [공식 현물 거래 규칙](https://coin.z.com/jp/corp/product/info/exchange/)을 확인해 결정했다.
- 지정가 매수 예약금은 `지정가 × 수량 + 동일 금액의 Taker 수수료`다. 예약금이 가용 JPY보다 크면 주문을 거부하고, 실제 Maker 체결 시 예약금과 실제 차감액의 차이를 가용 JPY로 반환한다.
- 지정가 매도는 주문 수량 전체를 예약하며 부분 체결은 허용하지 않는다.

#### 취득원가와 손익

- 매수 총차감액은 `매수대금 + 수수료`이며 이를 보유 자산의 총취득원가에 더한다. Maker 리베이트는 음수 수수료이므로 취득원가를 줄인다.
- 평균 매입가는 `총취득원가 / 총보유수량`이다. 추가 매수는 총취득원가와 총보유수량을 각각 더한 뒤 다시 계산한다.
- 부분 매도의 배분 취득원가는 `매도 전 총취득원가 × 매도수량 / 매도 전 총보유수량`이다. 전량 매도는 반올림 잔여 없이 전체 취득원가를 배분한다.
- 매도 순수령액은 `매도대금 - 수수료`이고 실현손익은 `순수령액 - 배분 취득원가`다. Maker 리베이트는 순수령액을 늘린다.
- 미실현손익은 `현재 Bid × 보유수량 - 총취득원가`이며, 아직 발생하지 않은 미래 매도 수수료는 차감하지 않는다. 미실현손익률은 `미실현손익 / 총취득원가`다.
- 전체 자산 평가에서도 보유 암호화폐는 현재 Bid로 평가한다.

#### JPY 표시

- 내부 JPY 값은 소수점 이하 12자리까지 유지한다.
- 사용자 UI에서는 정수 엔으로 반올림하고 정확히 절반이면 0에서 먼 방향으로 처리한 뒤 `¥1,234` 형식으로 표시한다.
- 거래 및 체결 내역에는 계산에 사용한 원본 10진 문자열을 보존해 UI 반올림으로 원장이 변하지 않도록 한다.

## 7. 외부 시장 데이터

### 7.1 주 데이터 공급자

`GMO Coin Public API`를 조건부 주 데이터 공급자로 사용한다. 2026-08-13 기준 기술 적합성은 확인됐으며, 배포용 연동 확정에는 제3자 앱의 데이터 재표시와 Cloudflare 정기 조회에 대한 GMO Coin의 서면 확인이 필요하다.

| 방식 | 사용 목적 |
|---|---|
| REST API | 현재 시세, 고가/저가, 거래량, KLine/OHLCV 등 조회 |
| Public WebSocket | Bid, Ask, Last 등 실시간 시세 수신 |

Flutter 앱은 일반 시장 데이터를 GMO Coin Public API에서 직접 조회한다. Cloudflare 백엔드는 지정가 주문 체결 판정에 필요한 시장 데이터만 조회한다.

검증된 초기 데이터 흐름은 REST `GET /ticker`로 5개 종목의 초기 값을 확보한 뒤 Public WebSocket으로 갱신하는 방식이다. WebSocket ticker는 모든 종목의 초기 스냅샷이 즉시 도착한다고 가정하지 않는다.

### 7.2 이용 조건 확인

2026-08-13에 공식 API 문서, API 소개, 이용약관 목록과 사이트 정책을 확인했으나, 제3자 모바일 앱의 시세 재표시·가공·저장과 Cloudflare Worker의 정기 조회 허용 범위는 공개 자료만으로 확정할 수 없었다. 다음 조건을 명시한 문의 문안과 기술 검증 결과는 `docs/GMO_COIN_API_VALIDATION.md`에 기록한다.

- 비수익 앱
- 모의투자 앱
- 실제 거래 기능 없음
- Public REST 및 WebSocket 사용
- 시세 데이터 표시 목적

서면 허용을 받기 전에는 GMO Coin 로고, 제휴 또는 공인으로 오인될 표현을 사용하지 않는다. 시장 데이터 연동 구현 직전과 스토어 제출 전에도 최신 공식 조건을 다시 확인한다.

### 7.3 검증된 데이터 제약

- MVP 5개 종목의 ticker, orderbook, 1분봉과 주문 규칙 실응답을 확인했다.
- API의 가격, 수량, 거래량과 수수료 값은 문자열이므로 부동소수점으로 직접 변환하지 않는다.
- `YYYYMMDD` KLine 날짜는 일본시간 06:00에 전환된다.
- 거래가 없는 분에는 1분봉이 없을 수 있다. 빈 분을 임의의 봉으로 만들거나 지정가 체결 근거로 사용하지 않는다.
- Public WebSocket의 `subscribe`와 `unsubscribe`는 동일 IP에서 초당 1회가 상한이므로 종목 구독을 순차 처리한다.
- Public REST의 정량 호출 상한은 공개 문서에서 확인되지 않았으므로 GMO Coin 문의 후 조회 주기와 백오프를 결정한다.

### 7.4 대체 후보

`Coincheck Public API`는 GMO Coin이 제3자 데이터 표시 또는 백엔드 조회를 허용하지 않거나, 비용·표시 조건·호출 제한이 MVP 원칙과 충돌할 경우의 대체 후보이다. MVP에서 복수 공급자를 동시에 구현하지 않으며 대체 후보도 같은 기술·약관·비용 검증을 먼저 수행한다.

- Installation ID를 실명, 이메일, 전화번호, 광고 ID 또는 외부 계정과 결합하지 않는다.

- 직접 식별 정보는 수집하지 않지만 서버에 보존되는 Installation ID와 주문 데이터는 스토어 정책상 수집 데이터로 정확히 신고한다.

확인 결과가 현재 설계와 충돌하면 출시를 강행하지 않고 기능 또는 데이터 공급자 변경을 검토한다.

## 13. AI Agent 구현 체크리스트

AI Agent는 기능 작업 전에 다음 순서로 범위를 확인한다.

1. 요청이 실제 금융거래, 계정 연결, 추천 또는 수익 보장 기능을 포함하지 않는지 확인한다.
2. 이 문서에서 관련 항목의 결정 상태가 `확정`, `구현 시 결정`, `출시 전 확인` 중 무엇인지 확인한다.
3. `구현 시 결정` 항목이 필요하면 구현 전에 사용자와 합의하고 문서 및 TODO를 갱신한다.
4. 앱과 Cloudflare 백엔드의 책임 경계를 유지한다.
5. 무료 운영 원칙을 해치는 의존성이나 외부 서비스를 추가하지 않는다.
6. 사용자 노출 문구는 일본어, 개발 문서와 코드 주석은 한국어로 작성한다.
7. 금액, 주문 및 자산 데이터의 정합성을 검증할 테스트를 함께 고려한다.
8. 구현과 검증이 끝나면 관련 TODO 상태와 문서를 갱신한다.
